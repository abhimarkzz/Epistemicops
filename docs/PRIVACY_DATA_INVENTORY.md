# EpistemicOps — Privacy Data Inventory

**Application:** EpistemicOps (SRE Incident Command Center)  
**Environment:** Local-first engineering demonstration & investigation assistant  
**Audit Date:** 2026-09-29  
**Status:** Grounded in active codebase audit  

---

## 1. Summary of Data Practices

EpistemicOps is designed as a privacy-minimal, local-first operational tool. It does not require user accounts, does not collect personal contact information (names, emails, phone numbers), sets no cookies, and operates without client-side analytics or third-party tracking beacons.

The following inventory details every category of data processed by the application.

## 3. Personal Data Assessment

- **Personal Data Collected:** None. The application does not collect names, email addresses, physical addresses, phone numbers, government IDs, biometric data, or financial data.
- **Account Creation:** None. The application operates without sign-up, login, passwords, session tokens, or user profiles.
- **User-Entered Free Text:** In the current version, operator inputs are limited to mode selection buttons (`LIVE`, `BASE`, `DEMO`), incident selection cards, filter chips, and execution trigger buttons (`[RUN INVESTIGATION]`, `[EXECUTE RUNBOOK]`, `[RESET MEMORY BANK]`). There are no text input fields or contact forms collecting arbitrary user information.

---

## 4. Key Takeaways & Data Minimization Verification

1. **Local-First Architecture:** The backend and frontend execute entirely on `127.0.0.1`.
2. **Third-Party Boundary:** In Live mode, diagnostic snippets from local fixtures are sent to the configured LLM API (Groq or Gemini). In Demo mode, zero external network requests are made.
3. **Storage Minimization:** No cookies, no localStorage, no persistent browser tracking.
